# Возврат товара от клиента — дизайн

Дата: 2026-10-05. Утверждено владельцем в чате (решения ниже — его выбор).

## Зачем

Клиент привозит мешки обратно («привёз 50 мешков DIKHAN») не под конкретный
заказ. Разбирать вручную, из какого заказа эти мешки, долго. Как «Внести
оплату» сама раскладывает деньги по долгам, так «Возврат» сам раскладывает
мешки по отгруженным заказам клиента.

## Решения владельца

| Вопрос | Решение |
|---|---|
| Какие заказы | Отгруженные (`status="shipped"`), не только долговые; корзина не участвует |
| Что с деньгами | Выбирают в форме: **«Уменьшить долг»** или **«Деньги из кассы»** |
| Переплата на оплаченном заказе | Касса отдаёт деньги обычным кассовым возвратом оплаты; аванса у клиента нет |
| Больше, чем помещается | Не принимать: «Максимум N мешков …» |
| Вид в заказе и выписке | «Отгружено 100, возврат 30», сумма и долг — за 70 |
| Склад | Мешки приходят на склад, выбранный в форме (по умолчанию основной) |
| Порядок | От последней отгрузки к старой (предложено, владелец не возразил) |
| Валюта | Не выбирается: у каждого заказа своя; касса отдаёт в валюте заказа («Касса отдаёт: 60 $ и 14 000 ₸»), итоги по валютам не складываются |

## Подход

Позиция заказа получает счётчик `returned_quantity`; сам возврат —
отдельная запись `GoodsReturn` со строками `GoodsReturnLine` (позиция заказа,
мешки, цена позиции, сумма). Отгружено остаётся как было; деньги считаются за
`quantity − returned_quantity` в трёх общих местах суммы заказа:

- `Order.total_amount` (модель);
- `orders/querysets.py::item_value_sum` (SQL, ею же `with_order_amounts`);
- `orders/querysets.py::_item_totals_by_order`.

Поэтому долг, касса, «Долг · клиент», выписки и денежные отчёты сходятся без
правок по месту. Счётчики отгруженных мешков (грузчик, камеры, отгрузка) —
физика, они остаются на `quantity`.

Отвергнуто: уменьшать `quantity` (владелец выбрал «отгружено 100, возврат 30»);
отдельный «минус-заказ» на дату возврата (ломает раскладку по заказам).

## Раскладка (сервер, `apps/orders/goods_returns.py`)

Вход: клиент, склад, режим (`debt` | `cash`), строки `{product, bags}`.

Кандидаты — живые отгруженные заказы клиента (любой валюты), с позициями этой
муки, у которых есть цена и `quantity − returned_quantity > 0`; порядок —
обратный :func:`debt.oldest_debt_first` (новая отгрузка первой). Строки формы
идут по очереди; запас денег заказа общий для всех строк одного возврата.

- **`debt` — «Уменьшить долг».** Только заказы со свободным остатком к оплате
  (`debt.available_to_pay` > 0 — без оплаты в работе). На заказ — не больше
  `floor(свободный остаток / цена)` мешков: переплаты не возникает.
- **`cash` — «Деньги из кассы».** Только полностью оплаченные заказы
  (`order_remaining == 0`) с деньгами к возврату (Σ `Payment.available_for_refund`).
  На заказ — не больше `floor(к возврату / цена)` мешков. Сумма заказа
  выдаётся кассовыми возвратами `refunds.create_cash_refund` по его
  подтверждённым оплатам (сначала новая), причина «Возврат товара №<id>».

Не поместилось — 400 `goods_return_exceeds`:
«Максимум N мешков «мука» в счёт долга» / «… из кассы».

`preview=true` — только раскладка, без записи. Проведение под блокировкой
клиента и его заказов (`clients.services.lock_scoped_client`,
`lock_client_orders`), как «Внести оплату»; раскладка пересчитывается под
блокировкой.

Проведение (одна транзакция):
1. `GoodsReturn` + строки; `OrderItem.returned_quantity += bags`;
2. склад: `warehouse.services.return_stock` — движение причины
   `client_return` («Возврат от клиента») на выбранный склад (не «Приёмка»:
   производство не искажается);
3. `cash`: кассовые возвраты по оплатам; затем `sync_payment_status` заказов;
4. журнал: событие `goods_return` на каждый затронутый заказ
   («Возврат 30 мешков · 94 800 ₸ · в счёт долга / из кассы»).

## API

`POST /api/clients/{id}/goods-return/` — тело
`{warehouse, settlement: "debt"|"cash", lines: [{product, bags}], preview}`.

`GET` той же ручки — мука клиента, которую можно вернуть:
`{products: [{product, label, debt_bags, cash_bags}]}` (сколько поместится в каждом режиме).

Ответ — раскладка: `{settlement, bags, amounts: {валюта: сумма}, orders: [{order_id,
currency, shipped_at, amount, lines: [{label, bags, amount}]}]}`; после проведения ещё
`return_id`.

Права: `orders.edit`; режим `cash` дополнительно `payments.confirm` (им же
сейчас делают возврат оплаты). Клиент — в области отдела пользователя.

## Модели и миграции

- `OrderItem.returned_quantity` — `PositiveIntegerField(default=0, db_default=0)`.
- `GoodsReturn`: `client` (CASCADE — уходит вместе с клиентом при его
  удалении), `settlement`, `warehouse` (PROTECT), `created_by`
  (SET_NULL), `created_at`.
- `GoodsReturnLine`: `goods_return` (CASCADE, `lines`), `order_item`
  (CASCADE, `return_lines` — окончательная очистка корзины не должна падать),
  `bags`, `unit_price`, `amount`.
- `StockMovement.REASONS` + `("client_return", "Возврат от клиента")`.

## Защита

- `orders.services.replace_items` и `shipments.services.rollback_shipment` (и
  откат грузчика) отказывают заказу с возвратом: 400 `order_has_returns`
  («У заказа есть возврат товара — …»).
- Мешки — целые положительные; склад — активный; `cash` в USD — как и кассовый возврат.
- Двойное «Подтвердить» проводит возврат один раз (фронт держит запрос).
- Заказ, возвращённый целиком, — бейдж «Возвращён» вместо «Не оплачен»
  (`order-payment-badge.tsx`; правило `payment_status` не меняется).

## Фронт

- `/orders`: кнопка «Возврат» рядом с «Новый заказ» (право `orders.edit`).
- `components/orders/goods-return-modal.tsx` — окно в стиле «Нового заказа»
  без доставки: 1 «Клиент» (общий выбор клиента, вынесенный из `OrderForm`, не
  копия), 2 «Что вернули» (только мука клиента, под строкой «можно вернуть до N
  мешков»), сбоку «Склад», «Деньги: Уменьшить долг / Деньги из кассы». Внизу «Проверить» → раскладка
  сервера по заказам → «Подтвердить».
- Заказ (`/orders/[id]`): у позиции «100 мешков · возврат 30».
- `OrderItem` в `lib/types.ts`: `returned_quantity`.

## Выписка

`clients/reports/statements`: текст позиции «мука × 100 (возврат 30)»;
PDF/Excel — колонка «Возврат» после «Мешков», сумма за `quantity − returned`.

## Не входит

Отмена возврата; возврат из карточки одного заказа; смешанный режим
(часть в долг, часть деньгами) — два возврата; аванс/баланс клиента.

## Тесты

Раскладка `debt`/`cash` (порядок, лимит на заказ, общий запас денег по
строкам, валюта, корзина, без цены, оплата в работе), «Максимум N», склад
(движение `client_return`), кассовые возвраты и статус оплаты, суммы заказа в
трёх местах, выписка, права (`orders.edit`, `cash` без `payments.confirm` —
403, чужой отдел), защита отката и правки состава; фронт — форма, раскладка,
подтверждение.
