# Касса на телефоне: мобильный слой в духе Kaspi Pay

Статус: согласован в чате · 2026-09-12

## Задача

Раздел «Касса» (`/accounting`) на телефоне (< 768px) становится похож на
Kaspi Pay: главный экран-меню с живыми цифрами, подэкраны с кнопкой «назад»,
списки вместо таблиц, шторки вместо панелей, кольцевая диаграмма в отчёте.
Десктоп визуально не меняется. Ни одна функция десктопной кассы не теряется —
меняется только раскладка.

Референс — экраны Kaspi Pay: главная (карточка «Продажи за сегодня» + список
пунктов с иконкой, подзаголовком и «›»), «Отчёт по продажам» (строка периода,
кольцо с итогом в центре, переключатель разреза, легенда строками, операции
по дням).

## Границы

В скоупе: `frontend/src/app/accounting/page.tsx`, `components/transactions-section.tsx`,
небольшие правки `Modal`, `Topbar`/`AppShell`, новая мобильная ветка, одно
поле в `/reports/summary/` на бэкенде.

Вне скоупа (отдельным заходом): детальные страницы долгов
`/accounting/debts/clients/[id]` и `/accounting/debts/stores/[id]`; создание
оплат из кассы (живёт на странице заказа); нижний таб-бар.

## Решения

- **Ветвление по JS, не по CSS.** `useIsMobile()` (`max-width: 767px`,
  граница `md`, как у мобильных карточек заказов/клиентов). Одновременно
  живёт одно дерево: десктопное или мобильное. CSS-дублирование не подходит:
  «Транзакции» сами грузят и поллят данные, два экземпляра — двойные запросы;
  а у мобильной навигации есть экран «главная», которого нет на десктопе.
- **Экран — в URL.** `/accounting?view=<screen>`. На телефоне переход на
  подэкран — `router.push` (системная «назад» работает, ссылки открывают
  нужный экран). На десктопе тот же параметр синхронизирует вкладки через
  `router.replace` (без засорения истории, но с диплинками); внешний вид
  вкладок не меняется.
- **Общая логика — общая.** Данные, мутации, права, фильтры вынесены из
  `page.tsx` и `transactions-section.tsx` в хуки; десктоп и мобилка — два
  представления над ними. Копий бизнес-логики нет.
- **Дизайн-система прежняя.** Inter, shadcn-токены (`--card`, `--muted`,
  `--border`, `--success`, `--destructive`, `--ring`), `shadow-card`, светлая
  и тёмная тема. Без декоративных шрифтов, анимаций и текстур.

## Значения `view`

| Экран | `view` | Телефон | Десктоп |
|---|---|---|---|
| Главная-меню | `home` | да | → `overview` |
| Общее (карточки + отделы + долги) | `overview` | → `home` | да |
| Отчёт по поступлениям | `report` | да | → `overview` |
| Долги клиентов | `debts` | да | → `overview` |
| Заявки и оплаты | `confirm` | да | да |
| Журнал | `journal` | да | да |
| Транзакции | `transactions` | да | да |

Значение по умолчанию: телефон — `home`; десктоп — как сейчас (`overview`,
иначе `confirm`, иначе `transactions` по правам). Экран, недоступный по
правам, заменяется значением по умолчанию. Если на телефоне по правам
доступен ровно один пункт меню, `home` открывает его сразу, без кнопки
«назад».

Кнопка «‹» на подэкране: если экран открыт нашим `push` с главной — `router.back()`,
иначе (диплинк) — `router.replace("/accounting")`.

## Права (как сейчас)

- `canPayments = payments.confirm` — заявки и оплаты, журнал, карточка
  «Ожидает подтверждения».
- `canReports = reports.view` — отчёт, карточка «Поступления за сегодня».
- `canDebtEntry = reports.view || payments.create` — долги.
- `canTransactions = payments.view` — транзакции.
- `canReviewOrders = orders.view && orders.confirm` — сегмент «Заявки».
- `canCheckOverdue = clients.edit` — «Проверить просрочки».
- Магазины для фильтра: `reports.view && clients.view`.

## Мобильные экраны

Общее для подэкранов: в топбаре вместо «☰» — «‹ Касса» (проп `back` у
`Topbar`/`AppShell`), заголовок — название экрана, справа — иконка фильтров
(`SlidersHorizontal`) со счётчиком активных, если у экрана есть фильтры.
`description` страницы на телефоне не показывается.

### Главная (`home`)

1. Карточка-сводка сверху (аналог «Продажи за сегодня»):
   - с `reports.view`: «Поступления за сегодня» · чистое поступление за сегодня
     крупно · «›» → `report` с периодом «Сегодня»;
   - иначе с `payments.confirm`: «Ожидает подтверждения» · сумма очереди · «›»
     → `confirm`;
   - иначе карточки нет.
   Пока грузится — «—»; при ошибке — `ErrorAlert` с повтором под карточкой.
2. Список-меню `NavList` (иконка · название · подзаголовок · «›»), пункты по
   правам, подзаголовки с живыми цифрами из тех же трёх запросов, что сейчас
   делает вкладка «Общее» (без фильтров):
   - **Заявки и оплаты** (`HandCoins`): «3 заявки · 5 оплат на 240 000 ₸» —
     заявки: `count` из `/orders/?status_group=pending` (только при
     `canReviewOrders`), оплаты: `/orders/payments-queue/?summary=1`;
     без данных — «Очередь подтверждения».
   - **Долги клиентов** (`Users`): «12 клиентов · 1,2 млн ₸ · 2 с просрочкой»
     (`formatCompactCurrency`, валюты не складываются: крупно основная,
     остальные через «+»); без данных — «Остатки по клиентам».
   - **Транзакции** (`Receipt`): «Все платежи, возвраты и чеки».
   - **Журнал** (`History`): «Действия по оплатам».
   - **Отчёт по поступлениям** (`ChartPie`): «По отделам и способам оплаты».
   Порядок фиксированный, как выше.

Чтобы главная не делала лишних запросов: `/orders/?status_group=pending`
на главной запрашивается с `page_size=1` только ради `count`.

### Отчёт (`report`)

- Строка периода: чипы `Сегодня · Неделя · Месяц · Всё · Период…`
  (`aria-pressed`); «Период…» открывает шторку с двумя `date`-полями.
  По умолчанию — «Сегодня». Отдел и магазин — в шторке фильтров.
- Кольцо (`DonutChart`, SVG, без recharts): в центре чистое поступление в
  основной валюте и «N оплат». Под кольцом переключатель разреза
  (`Tabs variant="segment"`): **По отделам** (по умолчанию) / **По способу**.
- Легенда строками: цветная точка · название · сумма (нетто) · доля в %
  (· «N оплат», если есть счётчик). Сегменты с нулевым/отрицательным нетто в
  кольцо не попадают, в легенде остаются.
  - По отделам: `departments[].net_by_currency[currency]`, цвет — `color`
    отдела, счётчик — новое поле `payments`.
  - По способу: `income.by_method_by_currency[currency]` (новое поле),
    подписи `PAYMENT_METHOD_LABELS`, счётчики `income.payments_by_method`.
    Цвета фиксированные из токенов: `cash` — `--success`, `kaspi` — `--ring`,
    `invoice` — `--warning`, `card` — `--muted-foreground`. Если бэкенд
    старый и поля нет — два сегмента «Наличные/Безналичные» из
    `cash_by_currency`/`cashless_by_currency`.
- Ниже: строки «Поступило до возвратов» и «Возвращено» (только если были
  возвраты); «Также чистыми: 5 000 $» для других валют. Валюты не
  складываются.
- Пустой период: кольцо серое, «За период поступлений нет».

### Долги (`debts`)

- Заголовочная строка: «Дебиторка 1,2 млн ₸ · 12 клиентов · 2 с просрочкой».
- Поиск по клиенту/телефону (как сейчас, локальный); «Проверить просрочки»
  — иконка-кнопка (`RefreshCw`), результат — строкой под заголовком.
- Строки (`ActionCard`, тап → `/accounting/debts/clients/[id]`):
  слева имя и телефон, справа остаток красным крупно (`CurrencyAmounts`);
  подстрока «3 заказа · Частично оплачен · 2 магазина · 2 просрочки»
  (бейдж состояния оплаты как на десктопе: `debtPaymentState`).
- Ленивая отрисовка по 25 с «Показать ещё» — как сейчас.
- Фильтры в шторке: даты, отдел, магазин, остаток от–до, валюта остатка.

### Заявки и оплаты (`confirm`)

- Сегмент `[Оплаты · N] [Заявки · M]` (`Tabs variant="segment"`, счётчики
  из `queuePage.count` / `pendingPage.count`); «Заявки» только при
  `canReviewOrders`, тогда сегмента нет вовсе.
- Оплата: сумма крупно, строка «Заказ #12 · Клиент · QR · Магазин · принял …»,
  бейджи отдела и стадии; действия в строке: широкая основная кнопка
  («Оплата поступила» для `requested`, иначе «Подтвердить получение») и
  текстовая «Отклонить». Без права — подсказка как сейчас.
- Заявка: «Заказ #12», клиент · сумма, бейдж отдела; «Проверить и
  подтвердить» открывает текущую `OrderConfirmation` в `Modal` на весь экран
  (`mobileFullscreen`), «Отклонить» — текущий `OrderRejectionDialog`.
- Ошибка действия — `ActionError` над списком (и внутри модалки, как сейчас).
- «Показать ещё», поллинг 30 с, тосты — без изменений (тот же
  `useCashierQueue`).
- Фильтры в шторке: даты, отдел, магазин.

### Журнал (`journal`)

- События по дням: заголовок дня «Сегодня» / «Вчера» / «12 сентября, пт»;
  строка: сообщение, мета «14:02 · заказ #12 · клиент · сотрудник», кнопки
  «Вернуть на подтверждение» / «Восстановить» (с тем же `ConfirmDialog`).
- «Показать ещё» (50), фильтры в шторке: даты, отдел, магазин.

### Транзакции (`transactions`)

- Сводка одной карточкой: «Оплачено» крупно + разбивка по способам
  (`PaidMethodSummary`), строки «Возвращено» и «Операций».
- Поиск; чипы статусов со счётчиками в горизонтальной прокрутке; отдел —
  `FilterDropdown`; «Обновить» — иконка.
- Список по дням; строка: слева «PAY-000123 · Клиент» и «14:02 · QR · Kaspi QR»,
  справа сумма и бейдж статуса, под ним «возврат 5 000 ₸» / «5 000 ₸ в
  обработке» при наличии.
- **Тап по строке → шторка деталей** (`Modal variant="sheet"`): содержимое
  нынешнего окна статуса (сумма, клиент, «что означает / деньги / что
  дальше», журнал операции, история возвратов) **плюс список действий**
  `TransactionActions layout="list"`: Восстановить · Отправить счёт ·
  Открыть Kaspi QR · Скачать выписку · Вернуть оплату · Отклонить — те же
  условия и права, что у иконок в таблице. Действие закрывает шторку и
  открывает свою модалку (возврат / отклонение / восстановление / QR) —
  существующие компоненты без изменений.
- «Показать ещё», поллинг 15 с на первой странице — как сейчас.

## Фильтры

`CashFilters` и хелперы (`EMPTY_CASH_FILTERS`, `apiUrl`, `filtersAreValid`)
переезжают в `components/cashier/filters.ts`. Состояние — по экрану:
`overview`, `report`, `debts`, `confirm`, `journal` (десктоп использует
`overview/confirm/journal`, телефон — `report/debts/confirm/journal`).
Значение `report` по умолчанию — сегодня (`dateFrom = dateTo = today`),
остальные пустые. Пресеты периода: «Неделя» = последние 7 дней включая
сегодня, «Месяц» = с 1-го числа по сегодня, «Всё» = пусто.

Поля фильтров — один компонент `CashFilterFields` (даты, отдел, магазин,
опционально остаток); десктопная `CashFiltersPanel` и мобильная
`CashFiltersSheet` его оборачивают. Изменение применяется сразу (как
сейчас); в шторке кнопки «Сбросить» и «Готово». Ошибки диапазонов — те же
тексты.

## Матрица загрузки

Один набор хуков в `page.tsx`; активный URL зависит от `mobile` и `view`.

| Данные | Десктоп | Телефон |
|---|---|---|
| `/reports/summary/?section=income` | `overview` (фильтры overview) | `home` (сегодня, без прочих фильтров), `report` (фильтры report) |
| `/clients/debts/` | `overview` | `home` (без фильтров), `debts` (фильтры debts) |
| `/orders/payments-queue/?summary=1` | `overview` | `home` (без фильтров) |
| `/orders/?status_group=pending` (count) | — | `home` (`page_size=1`, при `canReviewOrders`) |
| очередь: `payments-queue` + `orders pending` | `confirm` | `confirm` |
| `/orders/cashier-log/` | `journal` | `journal` |
| `/payment-transactions/` | внутри транзакций | внутри транзакций |
| `/departments/`, `/stores/` | всегда / при праве | так же |

Поллинг: `overview`/`home` — 30 с (сводка+долги+очередь), `confirm` — 30 с
(как сейчас), транзакции — 15 с (внутри). После успешного действия в
очереди перезагружаются сводка, долги, очередь и журнал — как сейчас.

## Бэкенд: разбивка поступлений по способу

`apps/orders/reports.py`, `summary_report`:

- `_payment_events_by_day` группирует дополнительно по `method`;
  `_refund_events_by_day` — по `payment__method` (возврат уменьшает способ
  **исходной** оплаты, как `paid_by_method` в транзакциях).
- В `income` добавляются:
  - `by_method_by_currency`: `{валюта: {способ: нетто}}` — gross − refund по
    способу, строки денег (`as_money_strings`), включая нулевые/отрицательные
    значения при активности;
  - `payments_by_method`: `{способ: число подтверждённых оплат}`.
- В строки `departments[]` добавляется `payments` — число оплат отдела.
- Существующие поля и `days[]` не меняются; `cash`/`cashless` считаются как
  раньше (сумма по методам сохраняет прежние итоги).
- Тест в `tests/test_reports.py`: cash 3000 + kaspi 1000, завершённый возврат
  200 по kaspi-оплате (method `apipay`) → `by_method_by_currency.KZT ==
  {"cash": "3000.00", "kaspi": "800.00"}`, `payments_by_method == {"cash": 1,
  "kaspi": 1}`, `income.cashless == "800.00"`, у отдела `payments == 2`.

Фронт: `ReportSummary.income.by_method_by_currency?`,
`income.payments_by_method?`, `DepartmentReport.payments?` — опциональные
(старый бэкенд во время раскатки), с фолбэком «Наличные/Безналичные».
