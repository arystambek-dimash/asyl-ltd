# Импорт акта сверки 1С в карточку клиента — дизайн

13.10.2026, ветка `client-acts`. Решения владельца — в разделе «Решения».

## Задача

В карточке клиента кнопка «Импорт акта сверки»: сотрудник выбирает xlsx
«Акт сверки взаимных расчётов» из 1С, видит предпросмотр и переносит историю:
Дебет (реализация) → отгруженный заказ задним числом, Кредит (оплата) → оплата
долга. Кредит больше дебета → «мы должны клиенту». Валюта — из шапки акта.
Актов много и периоды пересекаются — повторно документ не переносится.

## Формат (реальный файл «Акт сверки № 00000000509 от 07.10.2026»)

Один лист. Шапка «Акт сверки № N от …», «за период с ДД.ММ.ГГГГ по ДД.ММ.ГГГГ».
Две половины: «По данным <мы>, USD» (левая) и «По данным <контрагент>, USD»
(правая, пустая — игнорируем). Строка «Дата | Документ | Дебет | Кредит»,
«Сальдо на начало …», строки документов, «Обороты за период», «Сальдо на
конец …». Дата строкой «10.06.26». «Счет-фактура (выданный)» — без сумм,
пропускается. Документы: «Реализация ТМЗ и услуг N от …» (дебет),
«Платежное поручение (входящее) N от …, Накладная/Чек …» (кредит).

## Решения

- **Переплата** (итог в пользу клиента) — переплатой на последнем заказе
  клиента в этой валюте → «К возврату»; в карточке клиента «Мы должны клиенту».
  Аванса/баланса клиента не вводим.
- **Строка заказа** — скрытый товар «Реализация по акту сверки (1С)»
  (`is_active=False`, 2 кг), 1 × сумма документа. Склад не трогается.
- **Способ оплаты** — новый «Банковский перевод» (`bank`, ₸ и $);
  «Приходный кассовый ордер» → наличные.
- **Пересечение с CRM** — предпросмотр показывает заказы/оплаты CRM этой
  валюты за период акта; «Импортировать с даты» по умолчанию — день после
  последней записи CRM; строки раньше пропускаются.

## Устройство

Новое приложение `apps/client_acts` (тема «Акт сверки 1С»):

- `parser.py` — xlsx → `ParsedAct` (номер, период, контрагент, валюта,
  сальдо, строки). Строгая проверка: шапка, колонки по тексту, суммы строк =
  «Обороты за период», сальдо начала + обороты = «Сальдо на конец».
  Документ с суммой неизвестного вида — отказ со списком строк.
- `models.ClientActDocument` — реестр перенесённых документов:
  клиент + валюта + документ уникальны; у реализации — заказ, у оплаты —
  её оплаты (M2M) и `unapplied` (ещё не разнесённый остаток — предоплата).
- `services.py`:
  - `preview_act` — новые/уже перенесённые документы, пересечение с CRM,
    дата начала, сальдо на начало, проблемы, итог по акту;
  - `import_act_chunk` — до N строк за запрос в одной транзакции: реализация →
    `create_staff_order(backdate shipped)` + разнести предоплату; оплата →
    `record_client_debt_payment` на свободный долг на её день, остаток — в
    `unapplied`. Когда строк не осталось — остаток предоплат переплатой на
    последний заказ (`record_staff_payment(allow_overpayment=True)`).
- `views.py` — `POST /api/clients/{id}/act-import/` (multipart: `file`,
  `start`, `preview`). Права: `orders.edit` + `orders.confirm` +
  `payments.create`; область отдела клиента.

Сальдо на начало (только при импорте с начала периода): совпадает с балансом
CRM на эту дату — ничего; в CRM ноль и сальдо в долг клиента — заказ «Сальдо
на начало»; иначе — отказ с обеими суммами.

Порционный импорт (≈25 строк за запрос): gunicorn/nginx режут запрос на 60 с,
а акт за год — сотни записей. Реестр делает импорт продолжаемым: закрытая
вкладка → тот же файл продолжит с места остановки.

Фронт: `lib/client-acts.ts` (API), `components/clients/client-act-import-modal.tsx`
(файл → предпросмотр → прогресс → итог, ошибки в окне), кнопка в шапке
`/clients/[id]`, «Мы должны клиенту» в плитке «Текущий долг»
(`summary.by_currency[*].overpaid` из `client_history`).

## Тесты

Парсер на реальном файле (171 реализация, 6 оплат, обороты, сальдо 5 675 в
пользу клиента) и на испорченных вариантах; импорт: предоплата разносится на
следующие отгрузки датой поступления, итог = сальдо акта, повтор файла ничего
не дублирует, порции продолжают друг друга, пересечение с CRM сдвигает дату,
права и область отдела.
