# Камера номера у конвейера

Пользователь уточнил: камеру `cam…` и модель распознавания должен выбирать
суперпользователь из frontend, отдельно для каждого конвейера отгрузки.
Модели: госномера грузовиков (`vehicle_number`) и номера вагонов (`wagon_number`).

## Реализация

Внутри окна камеры отгрузки добавлена вкладка «Камера номера». Она содержит
выбор камеры и модели, сохранение/удаление связи, просмотр основного потока
и ручную проверку распознавания. Настройки не запрашиваются и вкладка не
показывается обычному сотруднику, в том числе с `sys_permissions.manage`.

Новая таблица `ShippingTransportCamera` хранит отдельную связь для конвейера.
Миграция `0032_shipping_transport_camera` только добавляет таблицу; текущие
заказы и AI-сессии не преобразуются. На уровне БД закреплена уникальность
обоих источников, допустимые модели и запрет одинаковых камер в паре.

API:

- `GET /api/cameras/{conveyor}/transport-camera/` — сохранённая связь или
  `null`-поля, когда связь ещё не задана; чтение без изменения БД/AI.
- `PUT` туда же — `{number_camera, recognition_model}`, ответ с сохранённым
  состоянием. Повтор того же выбора идемпотентен.
- `DELETE` туда же — удалить связь, ответ 204, повтор допустим.
- `POST /api/cameras/{conveyor}/transport-camera/recognize/` — проверить
  номер по сохранённым настройкам, вернуть номер либо `null` и время проверки.

Все четыре операции проверяют `IsSuperUser`. Изменения выполняются под общей
блокировкой с запуском AI-сессий; менять связь во время активной погрузки
нельзя. Одна номерная камера не закрепляется за двумя конвейерами. Снятие
конвейера из общего списка также проверяет права на его существующую связь,
освобождает камеру номера и сохраняет изменение в журнале.

Ручная проверка получает JPEG основного потока и вызывает соответствующий
`/vehicle-number/detect` либо `/wagon-number/detect` в CV-сервисе. Контракт
ответа проверяется по реализации сервиса: принятие OCR, формат и согласованность
полей номера; вагон использует проверки длины и контрольной цифры, как
существующий монитор номеров. Несколько разных принятых номеров не превращаются
в произвольный выбор первого. Ошибка модели/кадра возвращает отдельную ошибку,
а не «пустое место погрузки». Ответ старой проверки отбрасывается, если другой
администратор успел изменить или удалить связь.

## Обнаруженные связанные проблемы

1. Основной поток был разрешён в `api_views/access.py` только для камеры
   проходной. Суперпользователь теперь может просматривать строгие `camNmain`
   aliases; это не открывает произвольные URL go2rtc.
2. Динамическое обнаружение новых камер должно регистрировать настоящий main
   alias наряду с sub/AI; иначе камера выше статического диапазона выбирается,
   но её основной поток недоступен. Main не подменяется потоком sub.
3. Удаление конвейера пользователем с общими административными правами могло
   бы обойти superuser-only удаление связи. Этот путь закрыт проверкой внутри
   той же транзакции.

## Граница текущего изменения

Выбор камеры и ручной тест номера работают отдельно от управления погрузкой.
Автоматическое сопоставление заказа и завершение при отъезде ещё не подключены.
Правило пользователя сохраняется: пока сам грузовик/вагон стоит на месте,
погрузка остаётся активной; нечитаемый номер, пауза мешков и ошибка камеры
не доказывают отъезд. Для такого решения требуется детектор присутствия
транспорта на выбранном ракурсе, а не результат этой ручной OCR-проверки.

## Проверки

- Полный backend: **2321 тест, 3 subtests прошли**, отдельная свежая PostgreSQL
  БД. Проверены ограничения БД, права всех операций, конфликты связей,
  активная погрузка, идемпотентность, смена настроек во время OCR и оба
  реальных формата ответа CV-сервиса.
- Полный frontend: **560 тестов в 83 файлах прошли**. Проверены сохранение,
  удаление, смена модели, ошибки, отмена запросов и поздние ответы.
  Финальный прогон использовал `--maxWorkers=2` для ограничения нагрузки
  локального стенда; таймауты тестов не увеличивались.
- ESLint, TypeScript, форматирование frontend, Ruff F/I и `git diff --check`
  без ошибок; production build успешен.
- `makemigrations --check --dry-run`: изменений схемы без миграции нет.
- [Браузерная проверка](2026-09-07-transport-camera-settings-browser.md):
  реальные Django endpoints и отдельная PostgreSQL БД; сохранение после
  повторного открытия, смена обеих моделей, номер/пустой результат/ошибка,
  запрет изменений при активной погрузке, удаление и права сотрудника.
  Проверены desktop 1440×1000 и mobile 390px; preview ограничен 320px,
  чтобы результат оставался рядом с настройками. После этой правки
  повторный production build и 30 связанных frontend-тестов прошли.
- Устранена гонка в существующем тесте обнаружения камер: фоновое обновление
  теперь завершается внутри контекста заглушки и не меняет кэш следующего
  теста. Рабочая логика обнаружения не изменялась ради теста.

Проверки OCR используют локальный HTTP-стенд; к production-камерам не
обращались. Читаемость реальных номеров, ракурс и качество установленной
модели нужно проверить кнопкой «Проверить распознавание» на объекте.
