# Приход и вывоз: уточнение аудита перед исправлением

## [MEDIUM] G01. Разделение направлений существует в данных, но не в маршрутах

**Файлы:** `frontend/src/app/grain/page.tsx`, `components/grain/wagon-table.tsx`, `app/grain/wagons/[id]/page.tsx`, `backend/apps/grain/views.py`, `urls.py`.

**Что происходит:** машина вывоза имеет `direction=passage`, но создаётся через `/grain/wagons/passage/`, открывается по `/grain/wagons/{id}` и обслуживается общим WagonViewSet с действиями лаборатории и силосов. Выбранное направление списка хранится только в local state; переход обратно по `/grain` открывает приход.

**Почему это проблема:** URL не отражает рабочий сценарий; закладка и возврат теряют раздел. Разрешённые действия приходится восстанавливать по разрозненным проверкам.

**Backend ↔ Frontend conflict:** данные различают направления, маршрутизация и навигация этого различия не сохраняют.

**Как исправить:** выделить `/grain/passages` и `/grain/passages/{id}` в UI, ресурс `/api/grain/passages/` с queryset только вывоза и ограниченным набором команд. Старые API оставить совместимыми; старую UI-ссылку перенаправлять по фактическому направлению записи.

**Риск изменения:** Medium.

## [MEDIUM] G02. Карточка вывоза показывает реквизиты и значения прихода

**Файлы:** `frontend/src/app/grain/wagons/[id]/page.tsx`, `backend/apps/grain/models.py`.

**Что происходит:** для машины показаны «История вагона», силос, точка разгрузки, тип зерна. Верхние показатели используют названия «Брутто»/«Тара», хотя в исторической схеме `gross_weight_kg` у вывоза означает вес пустой на въезде, а `tare_weight_kg` — гружёной на выезде. Семантически верные `entry_weight_kg`/`exit_weight_kg` уже есть в DTO.

**Почему это проблема:** оператор видит неверный смысл веса; отсутствие силоса выглядит как незавершённая настройка машины вывоза.

**Backend ↔ Frontend conflict:** UI трактует внутренние поля хранения как физическое брутто/тару для обоих направлений.

**Как исправить:** отдельные действия вывоза и прихода; для вывоза показывать груз, вес пустой, вес гружёной, вывезенное нетто и историю рейса. Убрать вагонные реквизиты из вывоза. Сохранить ID, исторические весовые поля и фото.

**Риск изменения:** Low для отображения; Medium для разделения компонентов с восстановлением незавершённого взвешивания.

## [MEDIUM] G03. Общая таблица переходов описывает два разных процесса

**Файлы:** `backend/apps/grain/statuses.py`, `services.py`.

**Что происходит:** `ensure_transition` не учитывает направление. Вывоз использует сохранённые статусы `at_silo` и промежуточный `inventoried`, хотя силос и приход зерна не затрагивает. Завершение пишет сообщения о вагоне.

**Почему это проблема:** общая таблица разрешает переходы лаборатории/разгрузки вне контекста направления; безопасность зависит от дополнительных проверок вызывающего кода. Названия скрывают смысл состояния вывоза.

**Как исправить:** отдельно задать разрешённые переходы вывоза и выбирать их по направлению. Сохранить старые значения статусов и атомарную цепочку завершения для совместимости журналов и установленной автоматики. Отображать смысл вывоза; исправить новые сообщения истории. Полное переименование модели/колонок и миграция исторических статусов требуют отдельного изменения и здесь не нужны.

**Риск изменения:** Medium; проверить ручное взвешивание, автоматику, повторные команды и ошибку выходного веса.

## [MEDIUM] G04. Открытая карточка не узнаёт о взвешивании автоматикой

**Файлы:** `frontend/src/app/grain/wagons/[id]/page.tsx`.

**Что происходит:** список опрашивается, но карточка обновляется только после собственного действия. Ошибка загрузки истории выглядит как пустой журнал, а ошибка повторного чтения карточки скрывается за имеющимися данными.

**Почему это проблема:** автоматический весовой цикл может завершить вывоз, пока карточка предлагает выполнить предыдущий шаг; пользователь не видит причину устаревания.

**Как исправить:** видимый последовательный polling карточки/истории, приостановленный на собственной мутации; показывать ошибки чтения и сохранять идемпотентный повтор при неопределённом результате.

**Риск изменения:** Medium.

## Границы исправления

Общее хранение рейсов сейчас связано с фото, весовыми захватами, OCR-событиями и блокировками автоматики. Разделение физических таблиц само по себе не решает перечисленные дефекты. В этой итерации меняются маршруты, границы команд, UI и проверки направления; формула вывоза `выход − вход`, первичные ключи и записи учёта сохраняются.

## Что изменено и проверено

- Реализованы собственные страницы и API `/grain/passages`. Старые API совместимы; старая UI-ссылка `/grain/wagons/{id}` перенаправляет вывоз в правильный раздел после чтения направления записи.
- Общая карточка разделена на отображение рейса, действия прихода и действия вывоза. Формы прихода, регистрации и вывоза вынесены из страницы списка. Сам workspace теперь 446 строк, карточка 391; каждый модуль действий менее 300 строк.
- API вывоза не раскрывает ID прихода и не предоставляет команды лаборатории, силосов или прихода на склад. Разрешённые переходы вывоза заданы отдельно с сохранением исторических значений статусов.
- Вес пустой/гружёной, груз и история рейса отображаются по смыслу вывоза. Новые записи взвешиваний называют въезд/выезд; старые журнальные сообщения не переписываются.
- Открытая карточка опрашивается каждые 5 секунд при видимости; команды и удаление приостанавливают опрос. Начало мутации отменяет старый запрос карточки. Ошибки чтения карточки/истории видны.
- Дополнительно найден и устранён CORS-дефект: доверенный frontend на другом origin теперь может отправить `Idempotency-Key`. Посторонний origin не разрешён.

Браузер проверен на production-сборке Next.js и настоящем Django с отдельной временной БД. Физические весы заменены тестовым источником: ошибка → видимый ответ «Весы сейчас недоступны» → успешный повтор с весом 10 760 кг → завершённый вывоз 7140 кг при въездном весе 3620 кг. Отдельный рейс завершён из backend вне UI: открытая карточка сама обновилась и убрала предыдущую кнопку. Проверены прямой URL вывоза, возврат в `/grain/passages` и redirect старого wagon URL. Скриншоты: `evidence/grain-passage-error.png`, `evidence/grain-passage-completed.png`.

Полный backend: 2142 теста + 3 subtests; frontend: 524 теста, format/lint/typecheck/build. Дополнительные проверки CORS/config: 68; финальных сообщений/цикла вывоза: 19. Миграции не требуются. Фактический Camera-PC/OCR и весовое оборудование локально не проверялись; сохранённые серверные сценарии автоматики покрыты тестами.
