# Проверка настройки камеры номера конвейера

Дата: 2026-09-07. Проверен production frontend и настоящий Django API с отдельной PostgreSQL `asyl_transport_settings_preview`; миграция cameras/0032 применена. Backend `127.0.0.1:8119`, frontend `127.0.0.1:3019`. Рабочая база и внешние сервисы не использовались.

Для внешнего оборудования использован локальный HTTP stub `127.0.0.1:18992`: он отдаёт JPEG и ответы существующих `/vehicle-number/detect` и `/wagon-number/detect`. `recognize_transport_number` и конфигурационные endpoints не подменены. Инвентарь камер и continuous runtime заданы локальными fixtures. urllib/httpx запрещают обращения к внешним хостам; `CAMERA_HOST=127.0.0.1`. Next не проксирует `/go2rtc`, поэтому реальный видеопоток на стенде отсутствует.

## Выполненные сценарии

| Сценарий | Результат |
| --- | --- |
| Новая связь | Пустые камера/модель, сохранение и проверка отключены; в списке только отдельные camN, без самого конвейера и cam_mac. |
| Сохранение и повторное открытие | cam1 → cam7 + vehicle_number: PUT 200; после закрытия и повторного открытия значения восстановлены GET 200; PostgreSQL подтверждает связь. |
| Госномер грузовика | Проверка читает `/api/frame.jpeg?src=cam7main`, вызывает `/vehicle-number/detect`; UI показывает `123ABC02`. |
| Смена камеры и модели | Выбраны cam8 + wagon_number; до сохранения кнопка проверки отключена. PUT 200 обновляет обе части связи атомарно, что подтверждено SQL. |
| Номер вагона | Читается cam8main и вызывается wagon detect; UI показывает все восемь цифр `00123456`, включая ведущие нули. |
| Нет распознанного номера | HTTP 200 с number=null → «Номер не распознан»; предыдущий результат удалён из панели. |
| Модель недоступна | Локальный OCR возвращает 503; endpoint возвращает 503, UI показывает «Выбранная модель распознавания недоступна на ПК камер». После восстановления повторная проверка успешна. |
| Активная отгрузка | В изолированной DB создана active counting session. UI PUT и DELETE получают 400 «Сначала завершите активную отгрузку этой камеры»; прежняя cam8/wagon_number связь остаётся в DB. |
| Удаление | После закрытия fixture session DELETE 204; связей в DB 0, селекты и результат очищены, проверка отключена. |
| Обычный сотрудник | Сотрудник с shipping и sys_permissions.manage не видит «Камера номера» в модальном окне; GET конфигурации возвращает 403. |
| Авторизация основного потока | Настоящие `/cameras/token/` и `/cameras/auth/`: superuser cam7main/cam8main → 204, обычный сотрудник → 403; обычный cam7 сотруднику → 204. |
| Побочные операции | До явного создания fixture session проверка номера не создала counting sessions и не изменила количество заказов; OCR сам по себе не начинает погрузку. |

На desktop preview ограничен высотой 320px, изображение сохраняет object-contain; на ширине 390px остаётся естественная меньшая высота. Настройки, сообщения и кнопки доступны без горизонтальной прокрутки. Снимки подтверждают рабочую вкладку, полный номер, ошибку и отсутствие вкладки у сотрудника.

## Ограничения

Распознавание проверено на согласованном HTTP-контракте локального stub, а не на реальных номерах и ракурсе. Точность OCR и воспроизведение реального main stream требуют ручной проверки на камерах предприятия. Автоматическая привязка заказа и определение отъезда не входят в эту настройку и не заявлены интерфейсом.

## Проверки после уменьшения preview

Повторный production build с `NEXT_PUBLIC_API_URL=http://127.0.0.1:8119/api` завершён успешно. Targeted Vitest: **30 passed**, scoped ESLint без ошибок. На финальной сборке повторены сохранение wagon-настройки, распознавание, ошибка OCR, active-session PUT400 и desktop/mobile screenshots. Измеренная высота preview: desktop ~320px, mobile ~201px; горизонтальный overflow отсутствует.

## Очистка

Браузерная сессия закрыта; Next3019, Django8119 и HTTP-stub18992 остановлены. Отдельная PostgreSQL `asyl_transport_settings_preview` удалена.
